Speaker notes · 0:00–0:35

Move the pointer first. See how the light follows? Each pixel needs one piece of information: how far it is from the mouse. Close pixels get brighter. Distant pixels stay dark. Let’s see how the GPU does that.

Speaker notes · 0:35–1:05

The CPU can calculate every pixel. We are choosing the GPU because the same simple rule has to run over and over. At 1920 by 1080 pixels and 60 frames per second, that is about 124 million pixel calculations each second. This is an example workload, not a measured speed or a claim that the CPU cannot cope. Both CPU and GPU can work in parallel. For this small spotlight, CSS is also a practical choice; a CSS effect may itself use the GPU through the browser. Here we use WebGPU to learn how to program the GPU directly.

Speaker notes · 1:05–1:45

The CPU keeps the page working and reads the mouse. The GPU applies a similar calculation to lots of data. Move over this diagram: the CPU sends a position, and the GPU colours the mosaic. Both can work in parallel. This is an analogy, not a count of GPU cores, and it does not mean every pixel runs at once.

Speaker notes · 2:25–3:15

Drag the outlined pixel toward the mouse. The first line measures the distance. The second turns it into brightness. At the centre, the value is one. At 180 pixels away, it reaches zero. Beyond that it stays at zero. The next slide lets us change that radius.
